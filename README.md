  Linux Router (Debian 13 · wired · dual stack · nftables)

Turn an x86 industrial PC into a wired-only, dual-stack router with a clean Web console for system status, LAN/DHCP/IPv6 configuration, connected clients and maintenance.

This branch is a fork of [Jaksay/Linux-Router](https://github.com/Jaksay/Linux-Router) targeting a **minimal Debian 13 (trixie) install** on x86 hardware. Everything it needs is either part of the minimal install or a single `apt install` away.

![Linux Router Web Console](docs/assets/linux-router-web-console.png)

## Differences from upstream

| Area | Upstream | This branch |
| --- | --- | --- |
| Wireless | Wi-Fi client, hotspot, AP+STA, hotspot keepalive | **Removed**, wired only |
| Forwarding | `iptables` + NetworkManager `ipv4.method shared` | **nftables** (Debian 13 default), rules generated by the panel |
| IPv6 | Not supported | **Dual stack**: WAN SLAAC/DHCPv6, LAN **ISP prefix delegation**, ULA+NAT66 or a static global prefix |
| DHCP/DNS | `dnsmasq-base` used only by the hotspot | `dnsmasq` as a service: DHCPv4, RA, DHCPv6 and LAN DNS |
| Dependencies | `iptables`, `iw`, `wpa_supplicant` | All removed; only Flask/Gunicorn/NetworkManager/dnsmasq/nftables |
| Pages | Overview / Deps / Wired / Wi-Fi / Hotspot / Tools / Clients / Settings | Overview / Deps / Wired / **Router** / Clients / Tools / Settings |

## Highlights

- **Overview**: host, CPU, memory, disk, active connections with IPv4 and IPv6 addresses, NIC hardware
- **Router page**: pick WAN/LAN NICs, LAN IPv4 subnet, DHCP pool and lease, upstream DNS, MTU, IPv6 mode and prefix — apply in one click
- **Wired page**: per-NIC link state, speed, role, IPv4/IPv6 addresses, gateways, DNS, config method
- **Clients page**: dnsmasq leases merged with the neighbour table — IPv4, IPv6, MAC, lease time left, online state
- **Dependencies page**: component/service/forwarding/NAT health checks with one-click repairs
- **Tools page**: Tailscale helpers, service monitor, reboot

## Requirements

- x86_64 box with at least two wired NICs (WAN / LAN)
- Debian 13 minimal install with systemd and apt
- Interfaces managed by NetworkManager (the installer enables it)

Packages installed by the installer (everything else comes from Debian itself):

```text
python3 python3-flask gunicorn network-manager dnsmasq nftables iproute2 udev curl tar ca-certificates
```

The kernel side (`nf_tables`, `nf_nat`, `nft_chain_nat`) ships with the Debian kernel; no extra modules or builds.

## Install

From a local copy of this repository (simplest):

```bash
sudo bash /path/to/Linux-Router/install.sh install --source-dir /path/to/Linux-Router
```

Or from your own fork/branch:

```bash
curl -fsSL https://raw.githubusercontent.com/<you>/Linux-Router/<branch>/install.sh \
  -o /tmp/linux-router-install.sh
sudo bash /tmp/linux-router-install.sh install
```

`--archive-url https://.../source.tar.gz` works too.

The installer installs the packages, deploys to `/opt/linux-router` (data in `/var/lib/linux-router`),
creates the `router-panel` service account, enables IPv4 and IPv6 forwarding, seeds
`/etc/nftables.d/90-linux-router.nft` and `/etc/dnsmasq.d/linux-router.conf`, makes sure both include
directories are wired into `/etc/nftables.conf` and `/etc/dnsmasq.conf`, enables `nftables.service`,
`dnsmasq.service` and the two panel services, and disables `systemd-resolved` when it holds port 53.

## First run

Open `http://<lan-ip>/`, log in as `admin` with the password printed at the end of the install, then go to **路由 (Router)**:

1. WAN interface — the NIC connected to the modem/uplink (IPv4 comes from that NetworkManager profile)
2. LAN interface — the NIC connected to your switch; the panel creates a `linux-router-lan` profile using the first usable address of the subnet
3. LAN IPv4 subnet (default `192.168.50.0/24`), DHCP pool, lease time
4. IPv6 mode (see below)
5. Apply

Applying writes the dnsmasq config, brings up the LAN address, loads the nftables ruleset, enables forwarding
and restarts dnsmasq. If you changed the LAN address, reopen the panel on the new address.

## IPv6 modes

| Mode | Use case | LAN prefix | NAT66 |
| --- | --- | --- | --- |
| `ISP prefix delegation` | Bridged ONT, the box dials PPPoE itself | first /64 out of the delegated prefix | off |
| `ULA + NAT66` (default) | No ISP IPv6, or the ONT routes | auto-generated `fdxx:xxxx:xxxx::/64` | on |
| `Global prefix (routed)` | You already know a static /64 | your `2408:...::/64` | off |
| `Off` | IPv4 only | none | off |

The WAN side defaults to “WAN auto IPv6”, which sets `ipv6.method auto` (SLAAC + DHCPv6) on the uplink profile.
With PPPoE the WAN must be **ppp0** (the logical interface), not the physical NIC.

### How PD mode works

NetworkManager still has no DHCPv6-PD support, so PD mode runs a dedicated `dhcpcd` instance that only does
prefix delegation:

```text
WAN(ppp0) --DHCPv6-PD--> dhcpcd --ia_pd--> 2408:...:2f00::/60
                                            └─ first /64 assigned to LAN(enp2s0)
                                               └─ hook rewrites the dnsmasq RA prefix and restarts it
```

- One extra package: `dhcpcd` (Debian 13 main). Install with `--with-pd`, or from the Dependencies page
- It uses its own config `/etc/linux-router/dhcpcd.conf` and its own unit `linux-router-pd.service`; `/etc/dhcpcd.conf` is never touched
- `noipv4` + `noipv6rs` + `nohook resolv.conf, hostname`: IPv4, the WAN address and DNS stay with NetworkManager
- The LAN IPv6 address belongs to dhcpcd, so the LAN profile is set to `ipv6.method ignore` to keep NM from flushing it
- **Renumbering**: the ISP changing the prefix fires `DELEGATED6`, the hook calls `pd_hook.py`, which recomputes the LAN /64, rewrites dnsmasq and restarts it — clients pick up the new RA
- **Lost delegation** (`EXPIRE6`/`STOP6`): the prefix is cleared and RA stops, no stale addresses

Verify with:

```bash
systemctl status linux-router-pd --no-pager
ip -6 addr show dev <LAN> scope global
cat /var/lib/linux-router/pd.json
journalctl -u linux-router-pd -n 50 --no-pager
```

> PD only works if the ISP actually delegates (most residential links hand out /60 or /56, and only when the
> ONT is bridged and the router dials). With an ONT in router mode the prefix never reaches you — use ULA + NAT66.

## Access control (inbound filtering)

The default is **open**: NAT only, nothing is filtered. **With a delegated or static global prefix the LAN holds
public IPv6 addresses, so you must switch to protect** — otherwise every LAN device is directly reachable.

Protect mode adds `inet lr_input` (`policy drop`) and turns the forward chain into `policy drop`:

| Allowed | Purpose |
| --- | --- |
| established/related, ICMP, ICMPv6 | required for PMTU and neighbour discovery |
| `lo` | loopback (health checks) |
| WAN `udp 68/546` | DHCPv4 / DHCPv6 client replies |
| LAN `tcp 22/53/80` + your extras | SSH, DNS, panel |
| LAN `udp 53/67/547` | DNS, DHCPv4 server, DHCPv6 server |
| `tailscale0` | Tailscale remote access and subnet routes |
| WAN custom TCP/UDP | only when you need to reach the box from outside |

Forwarding then only allows `iifname <LAN>` and `tailscale0`: the LAN can get out, the outside cannot get in.

> ⚠️ If you SSH in over the WAN, put `22` in “WAN open TCP ports” **before** enabling protect mode.
> ⚠️ There is no port forwarding (DNAT) yet. Opening an inbound port to a LAN host means writing a dnat rule by hand.

## Running sing-box / transparent proxy

It works: sing-box only manages the tables it creates, so TUN mode and `auto_redirect` do not collide with
`lr_forward` / `lr_nat` / `lr_input`. Four things still need attention, or traffic silently bypasses the proxy:

1. **Routing loop** — TUN `auto_route` points the default route at tun0, which also captures the router's own
   traffic. Set `bind_interface: "ppp0"` (or `inet4_bind_address`) on the outbound.
2. **IPv6 leak** — with PD the LAN has public IPv6; a TUN with only `inet4_address` lets IPv6 go direct.
   Add `inet6_address` + `auto_route` for full coverage, or at least keep access control on protect.
3. **DNS ownership** — LAN clients use the local dnsmasq. To make sing-box DNS rules apply, set “upstream DNS”
   to `127.0.0.1#5353` (sing-box dns listening on `127.0.0.1:5353`). The panel then writes `no-resolv`, so
   dnsmasq stops appending `/etc/resolv.conf` and queries cannot leak to the ISP.
4. **Never `nft flush ruleset`** — it wipes our tables and NAT/filtering die instantly. Use
   `systemctl reload nftables` after editing rules.

The sing-box Clash API (default 9090) is an input service: add `9090` to “LAN open TCP ports” in protect mode.

## nftables layout

The panel writes `/etc/nftables.d/90-linux-router.nft`, pulled in by `include "/etc/nftables.d/*.nft"` in
`/etc/nftables.conf` and loaded by `nftables.service` at boot:

```nft
table inet lr_forward { ... }   # forward chain: LAN<->WAN, LAN<->LAN, IPv6 ND/PMTU
table ip   lr_nat    { ... }    # IPv4 masquerade with a counter the panel reads
table ip6  lr_nat6   { ... }    # IPv6 masquerade, ULA mode only
```

- The `input` chain is never touched, so the panel cannot lock you out
- Tables are deleted and recreated on every load, so `nft -f` / `systemctl reload nftables` is idempotent
- Inspect with `sudo nft list ruleset`, counters with `sudo nft list chain ip lr_nat postrouting`

## Troubleshooting

```bash
systemctl status router-panel router-panel-agent dnsmasq nftables --no-pager
ip -br addr; ip -6 route show default
nmcli -t -f DEVICE,TYPE,STATE,CONNECTION device status
sysctl net.ipv4.ip_forward net.ipv6.conf.all.forwarding
nft list chain ip lr_nat postrouting
cat /var/lib/misc/dnsmasq.leases
```

- **Clients get no address**: is `dnsmasq` running, does `/etc/dnsmasq.d/linux-router.conf` point at the LAN NIC, is port 53 taken by `systemd-resolved`?
- **Address but no internet**: `ip_forward`, masquerade rule present, WAN has a default route
- **No IPv6**: IPv6 forwarding on, `lr_nat6` present in ULA mode, LAN NIC has `fdxx::1/64`
