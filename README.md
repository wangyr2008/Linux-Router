  Linux Router
</h1>

**Turn a small x86 box into a wired-only, dual-stack Debian router with a usable web console.**

Built for a minimal Debian 13 (trixie) install, using only components that ship with
the system or need a single `apt install`: no wireless, no iptables, no NetworkManager —
forwarding and NAT are handled entirely by nftables.

![Web console](docs/assets/linux-router-web-console.png)

> A fork of [Jaksay/Linux-Router](https://github.com/Jaksay/Linux-Router). Wi-Fi and
> hotspot support were removed in favour of `systemd-networkd` + `nftables` + `dnsmasq`,
> and the things a home router actually needs were added: dual stack, shaping,
> inbound filtering, backup.

## Features

| Page | What it shows |
| --- | --- |
| Overview | host / CPU / memory / disk / uptime, active connections (IPv4 + IPv6), NIC hardware |
| Router | WAN mode (DHCP / PPPoE), LAN subnet, DHCP pool and lease, upstream DNS, MTU, four IPv6 modes, access control, one-click apply |
| Wired | per-NIC role, link state, speed, IPv4/IPv6 addresses, gateways, DNS |
| Clients | dnsmasq leases merged with the neighbour table; **device labels** and **static address bindings** (MAC → fixed IP) |
| Dependencies | component / service / forwarding / NAT / DNS health checks with one-click repairs |
| Tools | service monitor (runtime state + **is-enabled**), Tailscale helpers, reboot |
| Settings | admin password, CAKE shaping, **backup and restore** |

Also:

- **Dual stack** — WAN via SLAAC/DHCPv6; LAN via ISP prefix delegation, ULA + NAT66, a static global prefix, or off
- **CAKE shaping** — enter your line rate in Mbit/s; upload shaped on the WAN egress, download mirrored through `ifb-lr`
- **Access control** — open or protect; protect drops new inbound from the WAN and allows DHCP, ICMPv6, LAN and Tailscale
- **Backup / restore** — one JSON with the configuration plus a list of package names (no `.deb`)
- **No nmcli** — network state comes from `ip -j` and `/sys`, so the panel does not depend on NetworkManager

## Differences from upstream

| Area | Upstream | This branch |
| --- | --- | --- |
| Wireless | Wi-Fi client, hotspot, AP+STA, hotspot keepalive | **Removed**, wired only |
| Forwarding | `iptables` + NetworkManager `shared` | **nftables**, rules generated by the panel |
| IPv6 | Not supported | **Dual stack**: PD / ULA+NAT66 / static prefix / off |
| Network stack | NetworkManager | **systemd-networkd** + `pppd` (PPPoE dial only) |
| DHCP/DNS | `dnsmasq-base` only for the hotspot | `dnsmasq` as a service: DHCPv4 + LAN DNS (IPv6 RAs come from networkd) |
| Dependencies | `iptables`, `iw`, `wpasupplicant` | all removed |

## Requirements

- x86_64 box with at least two wired NICs (WAN / LAN)
- Debian 13 minimal install (systemd + apt)
- 1 GB RAM and 4 GB disk is plenty

Packages installed by the installer (everything else ships with Debian):

```text
python3 python3-flask gunicorn systemd dnsmasq nftables iproute2 udev ppp curl tar ca-certificates
```

`nf_tables`, `nf_nat`, `sch_cake` and `ifb` are in-kernel modules of the Debian kernel; nothing to build.

## Install

> Replacing an existing router? Follow [the on-site checklist](docs/INSTALL-CHECKLIST.md)
> first: it covers the sudo / user-group quirks of a minimal install, the DVD source
> error, clock and DNS checks, and the cut-over / rollback steps.

### 1. Bootstrap script (recommended behind restrictive networks)

`get.sh` tries GitHub directly and then a few public mirrors, and passes the mirror
that worked to `install.sh` so the source archive comes from the same endpoint:

```bash
curl -fsSL https://raw.githubusercontent.com/wangyr2008/Linux-Router/main/get.sh -o /tmp/lr.sh
sudo bash /tmp/lr.sh install
```

Force a specific mirror (or list the built-in ones):

```bash
sudo bash /tmp/lr.sh install --mirror https://ghfast.top/
sudo bash /tmp/lr.sh --list-mirrors
```

### 2. Local source (most reliable, no network needed)

Copy the repository to the box and unpack it:

```bash
cd /root/Linux-Router
sudo bash install.sh install --source-dir /root/Linux-Router
```

The installer detects that the script sits inside a source tree, so `--source-dir` is optional.

### 3. From your own repository / branch

```bash
sudo bash install.sh install --repo https://github.com/<you>/Linux-Router.git --branch main
```

### What the installer does

- Installs the packages, deploys to `/opt/linux-router` (data in `/var/lib/linux-router`), creates the `router-panel` service account
- Seeds `/etc/nftables.d/90-linux-router.nft` and `/etc/dnsmasq.d/linux-router.conf`, and makes sure both include directories are wired in
- Enables IPv4/IPv6 forwarding, `nftables`, `dnsmasq`, `systemd-networkd` and the two panel services
- **Leaves your NICs alone** — the panel takes them over when you press Apply (it stops NetworkManager / dhcpcd / ifupdown for those interfaces)

## First run

Open `http://<device-ip>/`, log in as `admin` with the password printed at the end of the
install, then go to **路由 (Router)**:

1. **WAN mode** — PPPoE for a bridged ONT (enter the account and the physical NIC), or DHCP behind a router
2. **LAN interface** — the NIC connected to your switch
3. **LAN IPv4 subnet** (default `192.168.50.0/24`), DHCP pool, lease time
4. **IPv6 mode** (see below)
5. **Access control** — read the security section first if you manage the box over the WAN
6. Apply

Applying writes the `.network` files, the dnsmasq config and the nftables rules, then
restarts the affected services. **Changing the LAN address drops the current page** —
reopen it on the new address.

## Architecture

| Component | Responsibility |
| --- | --- |
| `systemd-networkd` | WAN DHCP/SLAAC, LAN static address, IPv6 RA/RDNSS, DHCPv6 prefix delegation |
| `pppd` (`linux-router-pppoe.service`) | PPPoE session only; creates `ppp0` |
| `dnsmasq` | LAN DHCPv4 and DNS, bound to the LAN addresses only |
| `nftables` | NAT, forwarding, inbound filtering (four `lr_*` tables) |
| CAKE / `ifb-lr` | egress shaping plus ingress mirroring for download shaping |

NetworkManager, dhcpcd and ifupdown are not used.

## IPv6 modes

| Mode | Use case | LAN prefix | NAT66 |
| --- | --- | --- | --- |
| ISP prefix delegation | Bridged ONT, the box dials PPPoE | first /64 of the delegated prefix | off |
| ULA + NAT66 (default) | No ISP IPv6, or the ONT routes | generated `fdxx:xxxx:xxxx::/64` | on |
| Static global prefix | You already have a fixed /64 | your `2408:...::/64` | off |
| Off | IPv4 only | none | off |

PD is done by networkd's `DHCPPrefixDelegation=` (systemd ≥ 250), so no extra daemon is
needed: the LAN `.network` sets `DHCPPrefixDelegation=yes` + `IPv6SendRA=yes` and both the
address and the RA follow a renumbered prefix. PPP links never receive an RA, hence
`[DHCPv6] WithoutRA=solicit` on `ppp0`.

> PD only works with a bridged ONT where the box dials itself. With the ONT in router mode
> the prefix never reaches you — use ULA + NAT66.

## Security (access control)

The default is **open**: NAT only, nothing filtered.

As soon as the LAN holds public addresses (PD or a static prefix) you **must switch to
protect**, otherwise every LAN device is directly reachable. Protect adds `inet lr_input`
(`policy drop`) and turns the forward chain into `policy drop`, allowing only:

established/related, ICMP/ICMPv6, `lo`, WAN DHCP replies, LAN 22/53/80 (plus your extras),
`tailscale0`, and any WAN TCP/UDP port you list explicitly.

> ⚠️ **Managing the panel from the WAN? Put the panel port (80) and SSH (22) in “WAN open TCP
> ports” before enabling protect**, or you lose access immediately. The panel refuses that
> apply and tells you why, but check it anyway.
>
> Locked out? On the local console run `nft delete table inet lr_input` to regain access,
> then fix the configuration in the panel (see DEPLOYMENT.md).

> ⚠️ There is **no port forwarding (DNAT)** yet. Exposing a LAN host to the internet means
> writing a dnat rule by hand.

## CAKE shaping

Enter your line rate in Mbit/s on the Settings page (upload required, download optional):

| Direction | Implementation |
| --- | --- |
| upload | `tc qdisc ... root cake bandwidth <n>mbit` on the WAN egress |
| download | mirrored to a dedicated `ifb-lr` device, then shaped |

- Written to `/etc/linux-router/cake.sh` plus `linux-router-cake.service`, applied at boot
- `linux-router-cake.timer` re-runs `ensure` every 5 minutes, so a recreated interface (PPPoE redial, NIC reset) gets its qdisc back; it is idempotent and never resets counters
- 85–95% of the nominal rate works best; a full-rate setting just builds a queue

## Backup and restore

Settings → 备份与恢复 exports one JSON: panel configuration (router/DHCP/IPv6/firewall/CAKE/credentials/labels/bindings),
`/etc/systemd/network/*.network`, ppp configuration, nftables and dnsmasq configuration,
sysctl, the CAKE and DNS sync scripts and units, plus a **list of package names** (no `.deb`).

Restore validates the format and version, **only writes paths from that list**, restores the
original modes, hands the data directory back to the panel account, installs missing packages
by name, and reloads only the affected services.

> The backup contains your PPPoE password and the panel password hash — do not leave it lying around.

## Running sing-box / transparent proxy

The rules do not collide (sing-box only manages its own tables), but four things need
attention or traffic silently bypasses the proxy:

1. **Routing loop** — TUN `auto_route` points the default route at tun0, capturing the router's own traffic. Set `bind_interface: "ppp0"` (or `inet4_bind_address`) on the outbound.
2. **IPv6 leak** — with a public prefix, a TUN with only `inet4_address` lets IPv6 go direct. Add `inet6_address` for full coverage.
3. **DNS ownership** — set “upstream DNS” to `127.0.0.1#5353` (sing-box DNS listener). The panel then writes `no-resolv`, so dnsmasq stops appending `/etc/resolv.conf` and queries cannot leak to the ISP.
4. **Never `nft flush ruleset`** — it wipes all four `lr_*` tables. Use `systemctl reload nftables` after editing rules.

The sing-box Clash API (default 9090) is an input service: add `9090` to “LAN open TCP ports” in protect mode.

## Troubleshooting

```bash
systemctl status router-panel router-panel-agent systemd-networkd dnsmasq nftables --no-pager
networkctl list && networkctl status <nic> --no-pager
ip -br addr; ip -6 route show default
cat /etc/resolv.conf
nft list chain ip lr_nat postrouting
cat /var/lib/misc/dnsmasq.leases
journalctl -u systemd-networkd -n 50 --no-pager
```

| Symptom | Check |
| --- | --- |
| Panel unreachable | `ss -ltnp \| grep :80`; did protect mode allow the panel port? |
| Clients get no address | is dnsmasq running; does `linux-router.conf` name the right LAN NIC |
| Address but no internet | `ip_forward`, masquerade in `lr_nat`, default route on the WAN |
| No IPv6 | IPv6 forwarding on; `lr_nat6` present in ULA mode |
| No delegated prefix | is the ONT bridged; `networkctl status <WAN>` for a Delegated Prefix |
| Local DNS broken | is `linux-router-dns.timer` running; `systemctl start linux-router-dns.service` to sync now |

Detailed steps are in [DEPLOYMENT.md](DEPLOYMENT.md).

## Upgrade and uninstall

```bash
# upgrade: replace program files and units, install any missing package
sudo bash install.sh upgrade --source-dir /root/Linux-Router

# uninstall (keeps credentials and router config)
sudo bash install.sh uninstall

# remove the data too
sudo bash install.sh uninstall --purge-data
```

**Upgrade** leaves the network configuration, runtime data, `/etc/nftables.d` and
`/etc/dnsmasq.d` untouched: it swaps `/opt/linux-router` and the two units, installs
whatever the package list is missing according to `dpkg` (skipping `apt-get update`
entirely when nothing is), and removes the `linux-router-pd.service`, dhcpcd hook and
`pd.json` left behind by the earlier dhcpcd-based build. If the upgrade also changed
networkd or PPPoE code, re-apply the router config from the panel once.

**Uninstall** removes the panel and `linux-router-*` units, the networkd / ppp / nftables /
dnsmasq configuration and the four `lr_*` tables, restores `/etc/network/interfaces` from
`interfaces.linux-router.bak`, and puts back forwarding plus the `dhcpcd` /
`systemd-resolved` states recorded at install time.
